# 青果果 GIF 表情包

这个仓库是一套做表情包的工具和说明书：给出一组主题和短句，就能做出以固定卡通女孩“青果果”为主角的透明背景动态表情（GIF），同时附上静态图（PNG）和一个可以在浏览器里翻看的预览页。

## 只想看看效果

直接打开在线预览：

<https://condorheroblog.github.io/qingguoguo-gif-stickers/>

页面上是已经做好的 27 张表情，可以点按钮在动态 GIF 和静态 PNG 之间切换，也可以切换亮色 / 暗色主题，方便看透明图在不同底色上的效果。看完就够的话，下面的内容都不用管。

## 它能做出什么

- 人物是固定的：圆脸、大棕眼、深棕齐刘海和双麻花辫，戴奶油色针织帽，穿米色毛衣。每张图的动作、表情、道具会随短句变化，人物本身不重新设计。
- 一条短句对应一张 GIF，短句会原样画在图上，顺序和大小写都保留（比如 `okk` 不会被改成 `OKK`）。
- 默认尺寸 320×320，透明背景，时长约 2 秒，循环播放。
- 每张 GIF 配一张同名 PNG，取自动画里最有代表性的一帧，图上的文字和排版跟 GIF 完全一致。
- 另外生成两张总览图、一个本地预览网页，以及一个打包好的 ZIP。

文字有四种暖色样式，默认是 A 版（奶油色字、深棕双描边）。想换样式时告诉 Codex 用第几种即可，具体配色写在 [SKILL.md](SKILL.md) 里。

## 开始之前，你需要准备

先理解三样东西：

- **skill**：可以理解成给 AI 助手看的一份工作说明书。一个文件夹里放着规则、参考图和小工具，AI 读到后会照着这套规则做事。这个仓库本身就是一个 skill。
- **仓库**：存放项目文件的文件夹，外加每次修改的历史记录。这个仓库放在 GitHub 上，所以既能下载，也能在线看。
- **git**：管理文件版本的工具，用来把仓库下载到本地、以及把改动传回去。不想装它也可以，GitHub 网页上能直接下载压缩包。

然后按需准备：

1. **能运行 Codex 的电脑。** Codex 是读取并执行这个 skill 的 AI 助手环境；普通聊天窗口读不到本地文件，做不了这件事。
2. **能生成图片的 AI 能力。** 人物的每个动作都要先生成连续帧图，这一步依赖你所用环境自带的图像生成功能。仓库里没有配置任何外部绘图接口，也没有密钥。
3. **Python 3 和 Pillow。** Pillow 是 Python 的图片处理库，用来把文字准确地画到每一帧上。没有的话，在命令行执行 `python3 -m pip install pillow`。
4. **一个支持中文的粗黑体字体文件。** macOS 一般自带 `/System/Library/Fonts/STHeiti Medium.ttc`，不用额外准备；Windows 或 Linux 需要自己找一个中文字体，运行时把字体路径传给脚本。
5. **git（可选）。** 只用来下载和更新仓库。
6. **GitHub 账号（可选）。** 只有你想把成品发布到网上给别人看时才需要。

不需要准备的是：自己的照片、修图软件、设计经验。这个仓库里的人物参考已经内置好了。

## 从哪一步开始

### 第 1 步：把仓库拿到本地

装了 git 的话，在命令行执行：

```sh
git clone https://github.com/condorheroblog/qingguoguo-gif-stickers.git
```

不想用命令行，就打开仓库页面，点绿色的 `Code` 按钮，选 `Download ZIP`，下载后解压。

### 第 2 步：放到 Codex 会读取的位置

把整个文件夹放进 Codex 的 skills 目录，最终应该能看到这样的路径：

```text
~/.codex/skills/qingguoguo-gif-stickers/SKILL.md
```

`~` 表示你的用户主目录。放好之后，Codex 才能识别到“青果果表情包”这个 skill。

### 第 3 步：告诉 Codex 你要什么

给一个主题，再给一组短句。比如：

> 用青果果表情包 skill，主题是睡前，关键词：晚安、好梦、睡了、明早见。

主题决定场景和道具，关键词就是图上的文字。只给主题、不给关键词时，它会自己拟 24 条短句直接开做。

默认流程不会先给你看样张、也不会停下来等你确认，而是直接做完一整套，所以关键词最好一次说清楚。

### 第 4 步：等它生成并检查

每个动作先生成一张多格图集（一张图里排着几帧画面），再用导出脚本加上文字、合成 GIF。完成后会告诉你成品放在哪里。

关于放在哪里，规则是这样的：

- 你明确说了成品路径，就用你给的路径。
- 你指定了某个表情包文件夹（比如 `work/a`），成品放在 `work/a/outputs/成品`。
- 两个都没说，才放在当前目录的 `outputs/成品`。
- 同名文件夹不会被覆盖，会自动变成 `成品-v2`、`成品-v3`。

### 第 5 步：看效果

打开成品文件夹里的 `index.html`，双击即可，不需要联网。里面能逐张看动态和静态图，也能切换明暗主题。

想发到网上，见下面“怎么发布到网上”。

## 仓库里的文件分别是干什么的

| 路径 | 作用 |
| --- | --- |
| `SKILL.md` | 核心说明书。写着人物长什么样、四种文字样式、制作步骤、成品规则和输出位置。Codex 实际执行时读的是它。 |
| `assets/qingguoguo-reference.png` | 内置人物参考图。每次生成前先看它，保证每张图里是同一个角色。只用于制作，不放进成品 ZIP；也不要拿去做其他用途或当成自己的素材再发布。 |
| `assets/text-styles-preview.png` | 四种文字样式的对照示意图，供制作时参考，不用展示给使用者。 |
| `scripts/export_frames.py` | 导出脚本。读取图集和一份清单，负责切帧、加文字、生成 GIF / PNG / 总览图 / 网页 / ZIP。它不抠图，也不生成动作。 |
| `output/` | 已经跑好的演示成品：27 张 GIF、27 张同名 PNG、两张总览图和 `index.html`。线上预览就是把它发布出去的结果。 |
| `.github/workflows/publish.yml` | 发布网页用。当 `output/` 里的文件被推到 `main` 分支，或在 GitHub 页面上手动触发时，自动把 `output/` 发布到 GitHub Pages。 |
| `.github/workflows/release.yml` | 生成发行说明用。推一个 `v` 开头的标签（比如 `v1.0.0`），或手动触发，它会整理提交记录并在 GitHub 上创建一个 Release。 |

## 手动运行导出脚本（进阶）

通常不用自己敲命令，Codex 会代劳。如果你已经有切好的图集，想单独跑导出，需要准备一份 `manifest.json` 清单，放在图集旁边。清单里说明用哪种文字样式、是否透明，以及每一条的：文字、图集文件、网格是几行几列、按什么顺序取帧、每帧停留多久、选第几帧做 PNG。每条文字不能重复。

命令只有一个：

```sh
python3 scripts/export_frames.py /绝对路径/manifest.json /绝对路径/输出目录 --font '/System/Library/Fonts/STHeiti Medium.ttc'
```

`--font` 是必填项。省略输出目录时，会退回到当前目录下的 `outputs/成品`。几个常见限制：每条至少两帧、每帧时长不少于 10 毫秒、所有帧必须来自同一张固定网格的图集（否则人物会跳动）、图集本身要带透明通道。

## 怎么发布到网上

仓库里已经有两个自动化流程，不需要自己写部署脚本：

- **发布网页**：把新的 `output/` 提交并推送到 `main`，`publish.yml` 会把 `output/` 目录整个发到 GitHub Pages，地址保持不变。第一次使用时，如果线上地址打不开，多半是仓库的 Pages 还没开启，需要到仓库设置里把 Pages 的来源指向部署分支。
- **发布版本**：打一个 `v` 开头的标签并推送，`release.yml` 会生成对应的 Release 说明。

## 遇到问题

- **线上页面打不开**：等一两分钟让部署跑完；仍未恢复就去仓库的 Actions 页面看 `Build and Deploy` 是否成功。
- **提示找不到字体或中文变方块**：`--font` 的路径不对，或这个字体不支持中文。macOS 用上面给的 STHeiti 路径，其他系统换成自己电脑上的中文字体文件。
- **提示文字重复**：同一套表情里每条短句必须唯一，改掉重复的那条。
- **画面不动或只有抖动**：导出脚本只负责切帧和加字，不会补动作。动作不够就重新生成图集。
- **环境不能生成图片**：这个流程就做不下去。不要用静态图反复平移来凑数，也不要换成外部付费接口。
